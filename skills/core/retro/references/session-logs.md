# Session logs

Where each harness keeps its session logs, their format, and how to read them. These formats are undocumented and may change: when a log does not match its row, say so and read what is there. For a harness not in the table, ask the user for a transcript path.

**Finding the current session.** Newest is not always current: another session or a subagent in the same directory can be newer. Never count a subagent session as the current one: a Claude Code file under `subagents/`, a Codex rollout whose `source.subagent` is set, an OpenCode row with a `parent_id`. Then:

1. When the harness exposes this session's own id to you, take the log with that id.
2. Otherwise take the newest remaining log for the working directory, unless more than one was active in the same window. Then name the candidates (id, start time, first user message) and ask which one is this session; never choose silently.

| Harness | Location | Format | How to read |
|---|---|---|---|
| Claude Code | `~/.claude/projects/<project>/<session-id>.jsonl`. `<project>` is the session's working directory with each non-alphanumeric character replaced by `-` (`/work/my.app` becomes `-work-my-app`); when unsure, match the `cwd` field. Subagent transcripts sit in `<session-id>/subagents/`, large tool outputs in `<session-id>/tool-results/`. | JSONL, one event per line. Lines with `type` `user` or `assistant` carry `message.content`: a string, or blocks of type `text`, `thinking`, `tool_use` (`name`, `input`) and `tool_result`. Each also has `timestamp`, `cwd`, `gitBranch` and `isSidechain`. Other line types are harness bookkeeping. | Find the current session as above among the files in its project folder. Filter with `jq` or a short script rather than loading a whole file: user text turns, tool calls with their inputs, and failed tool results. A `user` line holding only `tool_result` blocks is tool output, not the user; text the harness injects (system reminders, hook output) is not the user either. |
| Codex | `~/.codex/sessions/<yyyy>/<mm>/<dd>/rollout-<local-time>-<session-id>.jsonl` (`$CODEX_HOME` replaces `~/.codex` when set). Subagent threads get rollout files of their own. | JSONL, one `{timestamp, type, payload}` per line. The first line, `session_meta`, holds `id`, `cwd`, `git`, `cli_version` and `source` (`source.subagent` marks a subagent). `response_item` lines with `payload.type` `message` carry `role` (`user`, `assistant`, `developer`) and `content` blocks (`input_text`, `output_text`); `custom_tool_call` and `function_call` carry `name`, `input` or `arguments` and a `call_id` matched by the `..._output` line; `reasoning` is encrypted. `event_msg` lines with `payload.type` `item_completed` hold an `item`: `UserMessage`, `CommandExecution` (`command`, `exit_code`, `status`), `FileChange`. | Find a session by date folder, then by the `cwd` of its `session_meta`; find the current session as above among those files. Filter with `jq` or a short script: `user` messages, tool calls with their inputs, and `CommandExecution` items with `status` `failed` or a non-zero `exit_code`. A `user` message starting `# AGENTS.md instructions` or `<environment_context>` is injected by the harness, not the user; `developer` messages are harness text too. |
| Cursor | `~/.cursor/projects/<project>/agent-transcripts/<session-id>/<session-id>.jsonl`. `<project>` is the working directory without its leading `/`, each run of non-alphanumeric characters replaced by `-` (`/work/my.app` becomes `work-my-app`); when unsure, `~/.cursor/chats/<hash>/<session-id>/meta.json` gives the session's `cwd`. | JSONL with no timestamps. Lines with `role` `user` or `assistant` carry `message.content` blocks of type `text` or `tool_use` (`name`, `input`). Tool results are not recorded. A `{type: "turn_ended", status}` line closes a turn. | Find the current session as above among the transcripts in its project folder. Read user text turns and tool calls with their inputs. The user's own words sit inside `<user_query>`; `<timestamp>` and other tags around it are injected. With no tool results, find failures from the next tool calls, the `turn_ended` status and the git history. |
| OpenCode | `~/.local/share/opencode/opencode.db` (`$XDG_DATA_HOME` replaces `~/.local/share` when set). | SQLite. `session_v2` has one row per session: `id`, `directory`, `title`, `parent_id` (set for a subagent session), `version`, `time_created` in epoch milliseconds. `session_message` has `session_id`, `seq` (the order), `type` (`user`, `assistant`, `idle`) and a JSON `data`: a `user` holds `text`; an `assistant` holds `content` blocks of type `text`, `reasoning` or `tool` (`name`, `state.status` `completed` or `error`, `state.input`, `state.content`); an `idle` holds the turn's `outcome`. | Open the database read-only (`sqlite3 -readonly`, or Python's `sqlite3` with `file:<path>?mode=ro` where the CLI is missing); never write to it. Find the current session as above among the `session_v2` rows whose `directory` is the working directory and whose `parent_id` is unset. Select its `session_message` rows by `seq`: user text, tool blocks with their inputs, and tools whose `state.status` is `error`. |

T3 Code needs no row: its threads run through a provider harness and land in that harness's logs. Its own state database is internal and is not read.

Rows verified on 2026-11-06 against real logs from Claude Code 2.1.318, Codex CLI 0.166.0, Cursor's `cursor-agent` CLI 2026.10.22 and OpenCode 2.2.5.
